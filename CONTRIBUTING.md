# Contributing

## Branch naming

Use `<type>/<short-kebab-case-purpose>` for every working branch.

Allowed branch types:

- `feature` for user-facing capabilities
- `fix` for defect corrections
- `refactor` for behavior-preserving code improvements
- `test` for test-only changes
- `docs` for documentation-only changes
- `chore` for maintenance and tooling

Keep each branch focused on one concern, use lowercase words separated by
hyphens, and do not add personal or tool-specific prefixes.

Examples: `feature/comments`, `fix/missing-post-image`, and
`docs/local-setup`.
